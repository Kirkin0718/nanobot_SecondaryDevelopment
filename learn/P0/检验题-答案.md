## 题 1｜核心数据流

按顺序列出从「用户在 WebUI 发消息」到「用户看到回复」经过的主要组件（至少写出：Channel、MessageBus、AgentLoop、AgentRunner、Provider、Tools）。对每一步用 **一句话** 说明它做什么。

> **正确答案：**
>
> * 完整流程：WebUI → Channel（接收）→ MessageBus（分发）→ AgentLoop（调度）→ AgentRunner（执行）→ Provider（调用LLM）→ Tools（执行能力）→ 反向流回到WebUI
> * Channel ：不止是"信息通道"，具体负责接收来自不同入口（WebUI/Telegram/Discord等）的消息，并统一标准化
> * MessageBus ： 消息路由中枢 ，负责把消息派发给对应的AgentLoop实例，同时负责回复的回传
> * AgentRunner ： 一次完整对话周期的总控 （接收→推理→工具→回复→发布）
> * Provider：供应商，提供各种大模型的服务
> * Tool：模型可调用的能力

## 题 2｜Loop vs Runner

下面三个故障，你分别会优先打开哪个文件？`loop.py` / `runner.py` / 还是别的？并简述理由。

1. WebUI 能发消息，但回复始终回不到浏览器
2. 模型返回 429（限流）
3. Agent 明明该调 `list_dir`，却一直空回答、从不调 tool

> **正确答案：**
>
> 1. WebUI能发出，说明outbound / session 侧合理；回不来需要查看  **MessageBus/Channel的回传路径** ，优先看 `channel/webui.py` 或 `message_bus.py`
> 2. 429限流应查看 `runner.py` 或 `provider/` 下的重试逻辑
> 3. tool不调用优先看 `runner.py` 的 `_call_tools()` 逻辑，或 `tools/` 的注册情况，以及模型的 `tool_calls` 字段是否被正确解析。

用表格或分点说明：

## 题 4｜Sessions vs Memory

1. 刚聊过的 5 轮对话，主要落在哪条路径？
2. `memory/history.jsonl` 和 `sessions/*.jsonl` 各自服务谁？
3. Dream 大致干什么？触发周期在你的 config 里大概是多久？

> **正确答案：**
>
> 1. 最近5轮 → `sessions/{session_id}.jsonl`（完整消息流水）
> 2. `memory/history.jsonl`是 **Dream的原料** （所有原始对话的积累）
>    `sessions/*.jsonl`是 **会话级别的上下文窗口** ，用于构建当前对话的短期记忆
> 3. Dream ≈ 定期整合器，从 `history.jsonl` 提取高价值信息压入 `memory.md`。周期默认一般看看config里的 `dream.interval` 或 `dream.trigger_count`，我的周期是约每2小时

## 题 5｜扩展边界

若要给 nanobot 加「查今日天气」：

1. 你觉得应该加在哪里？（tool / channel / skill / loop.py 等）
2. 为什么 **不该** 改 `agent/loop.py`？
3. Skill 和 Tool 在这件事里分别扮演什么角色？（可简短）

> **正确答案：**
>
> 1. **加在tool** ，更准确：加在 `tools/weather.py`，并注册到 `tools/__init__.py`
> 2. Loop只做调度，不改能力。 **扩展功能侵入loop会破坏单一职责** ，而且每次改loop都要重启，不灵活
> 3. **Skill** = 更高层的能力组合（可能调多个tool + 固定流程）像是教何时/怎么用工具的说明书；**Tool** = 原子能力（查天气这个单一动作）。查天气本身是个 **Tool** ，如果要做"天气助手Skill"则可能是组合。

## 题 8｜开放题（选答）

* 用 3–5 句话描述：你现在对「什么是 Agent」的理解，以及 nanobot 里最关键的那一小段循环是什么。

> **正确答案：**
> Agent = 大模型（大脑） + 记忆系统（记忆） + 工具（手脚） + 反馈循环（学习），是具有学习、记忆、思考、行动能力的人工智能
> **nanobot最关键的循环** = `AgentLoop.run()`，它内部的核心是
>
> ```
> while not done:
>     response = runner.run(context)
>     if response.has_tool_calls:
>         tools.execute()
>         continue
>     else:
>         publish(response)
>         break
> ```
> 这个**推理-执行-再推理**的闭环，才是Agent区别于普通LLM聊天的本质。
